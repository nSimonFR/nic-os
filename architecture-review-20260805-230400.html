The finding under all eight candidates

This repo documents its duplication impeccably, in exactly the places where a function should have been extracted instead.

airtrail.nix:55  “same fix as sure-pg-setup”

ryot.nix:102   “pattern shared with airtrail-pg-setup”

nextcloud.nix:100  “same caveat as sure/airtrail”

epicgames-freegames.nix:73  “Mirrors monitoring.nix's telegramNotify”

claude-account-healthcheck.nix:17  “Kept local to this module so it stays self-contained”

Every one of those comments is a correct, load-bearing observation. Each one is also a missing seam, written down as prose instead of code.

Live defects found by this review — verified against the running host

  1. Karakeep is unbacked. 2.2 MB of live bookmark data at /var/lib/karakeep, outside /mnt/data, so storj-backup.nix:11 never sees it — and no karakeep-backup unit exists anywhere. Nothing in the repo asserts “service with a DB ⇒ backup exists”.
  2. A dead nightly pg_dump. backups.nix:18 dumps a ghostfolio database; grep across the repo matches that line and nothing else.
  3. The OOM guard skips two services. lib/heavy-services.nix omits karakeep-web, karakeep-workers, meilisearch, showmycards-* — so nixos-rebuild-safe never frees their RSS on a 3.9 GB box whose documented failure mode is exactly a rebuild-time watchdog reset.
  4. Shared skills ship without their assets. home/claude.nix:15-38 maps only SKILL.md, but its own header promises “adding a new one is just a directory”. shared/skills/linear/assets/linear-small.svg and LICENSE.txt reach Claude Code, Codex and pi as nothing. Only Hermes, which copies whole dirs, is correct.
  5. Every tailnet node is an Aperture admin. aperture-sync.nix:70-77 grants role = "admin" to src = [ "*" ].
  6. A systemd condition in the wrong section. nixos/beszel-agent.nix:18 puts ConditionPathExists inside serviceConfig, so it lands in [Service] and systemd ignores it; the unit restart-loops when the env file is absent. The rpi5 copy gets it right (monitoring.nix:45, unitConfig). Found only by diffing two copies of the same module.
  7. The live agent reads a manual describing deleted paths. rpi5/hermes/documents/TOOLS.md is rsync'd into ~/.hermes/ at hermes.nix:200 and tells Hermes its skills live in rpi5/picoclaw/skills/ — a directory removed two agent-generations ago.
  8. The only enforcement mechanism is broken. .githooks/commit-msg invokes commitlint.config.cjs, which does not exist in the repo (nor does package.json). core.hooksPath is unset, so nothing runs it.

None of these is a coding mistake. Each is the predictable output of a fact that lives in two places with nothing checking agreement.

Problem

A service is not a module — it is a diff smeared across up to nine files, so no single place can be checked for completeness.

Solution

One option interface per service that owns its ports, database, backup, exposure and tile; the six central lists become derived from it.

Evidence

  • · Top three most-churned files in the last 400 commits, excluding flake.lock: services-registry.nix (42), configuration.nix (41), flake.nix (40).
  • · Adding ShowMyCards (46a11cc) touched 6 files. Adding scale-bridge (740f0f0) touched 6.
  • · Every socket-activated service writes its two ports twice, module and registry, linked by a comment — “see services-registry.nix” — instead of a reference. 21 such facts.
  • · 4a87659 fix(serve): free port 3700 collision — Ryot vs Epic Free Games. Port 3700 was written four times across two files. Nothing allocates ports.
  • · Redis DB indices are tracked by prose comments in three files that disagree on the inventory (databases.nix:34, gramps-web.nix:36, reactive-resume.nix:140).
  • · services-registry.nix:130 cross-references “monitoring.nix:213” by line number. It is off by 7.
  • · Disabling one service takes two coordinated comment-outs (configuration.nix:194 + services-registry.nix:81), and the comment says so.

Wins

  • · locality: one service, one place
  • · leverage: one interface, 26 services
  • · ports allocated, not remembered
  • · backup gaps become eval errors
  • · registry shrinks to derived data
  • · deletes ~6 hand-synced lists

The precedent is already in the repo

Three real seams already work this way: services.socketActivate (13 callers, one uniform shape, zero escapes), services-registry.nix → two mechanically derived consumers, and databases.nix's _module.args (11 consumers of pgHost/redisName instead of hardcoding). This candidate extends a pattern the author already chose — it does not import a new one.

Two adapters justify the seam: real HTTP in prod, a fake in tests.

Problem

~5,200 lines of imperative logic have exactly one interface — a systemd unit on the live host — and zero tests, so every change is validated in production.

Solution

A scripts/lib/ module for the five copy-pasted helper families, config injected rather than read at import, and flake.checks running pytest.

Evidence

  • · No checks, no devShells, no formatter in flake.nix. No pytest, bats, or nixosTest anywhere. One CI workflow, and it only syncs the Tailscale ACL.
  • · steam-to-ryot.py:72-90 and spotify-to-ryot.py:53-71 — http_json, load_json, save_json, post_to_ryot are character-for-character identical.
  • · Nine independent log() definitions. Four idioms for “read an agenix file and strip it”. Four Ryot clients speaking three protocols, one of which drops to raw destructive psql DML (ryot-plex-import.sh:87).
  • · Exponential backoff is implemented once, in moxfield-sync.py:131, and reimplemented as a retry loop inside a Nix string at aperture-sync.nix:127. Everything else has none.
  • · Six different wiring mechanisms for “run this script”. Only papra-webhook-tagsync.py declares a Python dependency; a stray import requests elsewhere would build, deploy, and fail at 05:20 on a timer.
  • · writeShellApplication runs shellcheck and is used twice. writeShellScript does not and is used 42 times.
  • · moxfield-sync.py — 811 lines, DRY_RUN="0" set in Nix, destructive against a 618-card collection with no soft-delete upstream, no tests.
  • · The only fully argv-driven script, scripts/immich-nextcloud-sync.py, is also the only one nothing runs automatically — and is referenced nowhere in the repo.

Wins

  • · tests hit one interface
  • · no rebuild to validate a change
  • · locality: retry and backoff live once
  • · destructive syncs become testable
  • · shellcheck covers the shell
  • · breaks the rebuild→OOM feedback loop

Note on the convention

“No inline Nix scripts” exists as a rule — but only in the agent's user-level memory, not in the repo. CLAUDE.md is 968 bytes and covers commit authorship and skill placement only. The rule is invisible to anyone reading the repo and enforced by nothing, and compliance tracks when a file was last touched: papra.nix externalises all five of its scripts, while monitoring.nix externalises one and keeps 95 lines of curl/jq/sed inline beside it.

  • · Three files under rpi5/ (blogwatcher.nix, gogcli.nix, goplaces.nix) are pure derivations misfiled as host modules.

Problem

Host identity is passed in and then ignored, so shared modules hardcode one host's facts and the two NixOS hosts duplicate ~14 blocks of identical setup — with silent drift.

Solution

Name directories after hosts, extract a common/ module for the genuinely host-agnostic setup, and pass hostname into home-manager so per-host branching can be expressed.

Evidence

  • · hostname is a specialArg on all three system configs and has one consumer in the repo (macos/configuration.nix:33). Both NixOS hosts swallow it in ... and hardcode their own name instead.
  • · It reaches none of the four home-manager configs — so no module under home/ can distinguish BeAsT from rpi5. Both are Linux; isDarwin can't help.
  • · Consequence: home/default.nix:46-55 installs Star Citizen launcher paths on the headless Pi and the Mac. home/editors.nix installs VS Code, Zed and a Cursor extension activation on a 3.9 GB server. home/ssh.nix:9 points every host at a Bitwarden desktop-app socket.
  • · Fourteen duplicated blocks between the two NixOS hosts, with unintended drift: trusted-users is [root, nsimon] on one and [nsimon] on the other; experimental-features differs; journald caps 200M vs 500M.
  • · The same ed25519 public key literal appears in four files. The rpi5 substituter set plus its “garnix is dead” comment is stated twice, in flake.nix and rpi5/configuration.nix.
  • · The specialArgs tuple is spelled out at seven sites. tailnetFqdn, beastOllamaUrl, apertureUrl and tinyLlmGateUrl are passed to home-manager configs that have zero consumers of them — and omitted from two of the four arbitrarily.
  • · beastHost is consumed by nixos/immich-ml.nix:72 but omitted from BeAsT's specialArgs. It doesn't fail today only because the sole reference sits inside a # comment where Nix doesn't interpolate — a latent eval failure masked by luck.
  • · home/mcp.nix:21 hardcodes the public tailnet TLS name for a service on the same box, so the rpi5 reaches its own local MCP by going out and back. tailnetFqdn is available and unused.

Wins

  • · locality: host facts in the host dir
  • · drift becomes impossible, not unlikely
  • · home/ can branch per host
  • · one specialArgs binding, not seven

The pattern already exists, once

shared/tailscale.nix is imported by both NixOS hosts and differs only in arguments (role, enableSSH, advertiseRoutes). It shows exactly what the other fourteen blocks could look like. rpi5Params at flake.nix:235-244 shows the author already knows the specialArgs fix too.

Top recommendation

Tackle first

1 · Give a service one module

Every live defect in this review — the unbacked Karakeep database, the phantom ghostfolio dump, the OOM guard that skips two services, the port 3700 collision — is the same failure: a fact about one service written in two places with nothing checking agreement. Fix the shape and the whole class goes away, rather than being patched one entry at a time.

It is also where the churn is. The three most-edited files in the repo are the three central registries, and they are edited because a service has nowhere else to declare itself. The pattern to extend already exists in services.socketActivate — 13 call sites, one uniform interface, zero escapes.

Warm up with #2 (small, self-contained) Clear the ground with #8 first

Two things this repo does not have, and should

No CONTEXT.md. The repo has no domain glossary, so terms that clearly are domain concepts — surface, skill, service module, heavy service, socket-idle, proxied vs funnel — are defined only implicitly, in comments, inconsistently. Several findings above are drift between two readings of one undefined term.

No ADRs. Nothing here contradicts a recorded decision, because none are recorded — so hard-won reversals (garnix removed, Plane dropped, PicoClaw retired, ChatGPT native mitm abandoned) live in commit messages and the author's private memory rather than the repo. That is why the same dead paths keep resurfacing.
